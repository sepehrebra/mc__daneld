# برنامه مرحله‌ای Codex برای مهاجرت Mc_Daneld از FastAPI به Django

> مبنا: فایل `backend-spec.md` پیوست‌شده توسط مالک پروژه. این فایل قرارداد رسمی فرانت‌اند و بک‌اند است؛ بخش ۴ آن در تعارض‌ها بر بخش ۳ مقدم است. وضعیت واقعی کد فعلی و دیتابیس فقط پس از بررسی ریپازیتوری معلوم می‌شود.

## روش استفاده

1. `backend-spec.md` و این فایل را در مسیر `docs/` ریپازیتوری قرار بده (به ترتیب `docs/backend-spec.md` و `docs/CODEX_MIGRATION_PLAN.md`).
2. از شاخهٔ تمیز `main` یک شاخهٔ `feature/migrate-fastapi-to-django` بساز. در اولین مرحله هیچ فایلی نباید حذف یا بازنویسی شود.
3. دستورهای هر «گام» را جداگانه به Codex بده؛ **فقط پس از تأیید تست‌های همان گام** سراغ بعدی برو.
4. در هر نوبت، Codex فقط فایل‌های مرتبط و بخش‌های اشاره‌شدهٔ `backend-spec.md` را بخواند، تغییرات کوچک و مرتبط اعمال کند و فقط تست‌های مرتبط را اجرا کند. اسکن سراسری و گزارش‌های طولانی لازم نیست.
5. Codex پس از هر گام، در `docs/migration-progress.md` حداکثر ۸ خط شامل کارهای انجام‌شده، فایل‌های اصلی، نتیجهٔ تست‌ها، مشکل باقی‌مانده و دستور بعدی ثبت کند.
6. هیچ تغییری در API، نام فیلدها، وضعیت‌های HTTP، قالب تاریخ و امنیت مالکیت بدون تأیید مستند مجاز نیست. هر فرض ناگفته باید در فایل پیشرفت ثبت شود.

## گام ۱ — اسکلت Django و تنظیمات مشترک

```text
ساختار پروژه Django و DRF را کنار کد فعلی بساز، با سه app پیشنهادی accounts، farms و operations؛ جایگذاری نهایی را بر اساس ساختار واقعی ریپازیتوری تعیین کن. فقط تنظیمات اتصال SQLite با env، مسیر پایه /api/v1، CORS برای http://localhost:5173 و env، UTC/timezone و زیرساخت پاسخ خطای 401/404/409/422 را ایجاد کن. توجه: DRF در حالت پیش‌فرض برای اعتبارسنجی 400 می‌دهد و باید 422 قراردادی شود. فعلاً هیچ کدام از endpointهای تجاری را پیاده‌سازی نکن. یک تست سلامت راه‌اندازی و مسیر API اضافه و اجرا کن. مستند: بخش ۲ و ۱۱.
```

**معیار پایان:** سرور Django با دیتابیس آزمایشی راه‌اندازی می‌شود؛ خطای JSON قراردادی فراهم است.

## گام ۲ — مدل‌های دیتابیس و Migrationها

```text
طبق docs/backend-spec.md بخش‌های ۳، ۴، ۵ و ۱۱، مدل‌های هفت جدول users، auth_sessions، farms، plots، crop_seasons، operations، reminders را بساز. نام جدول/ستون‌ها، ارتباط‌ها، مقدارهای پیش‌فرض، محدودیت یکتایی، اعتبارسنجی، statusها، ایندکس‌های ضروری و created_at/updated_at با مستند منطبق باشند. از جدول پیش‌فرض auth_user یا django_session به جای کاربران و نشست‌های اختصاصی قرارداد استفاده نکن. اگر مدل‌ها نیاز به تعریف سفارشی user دارند، طراحی‌ای انتخاب کن که فیلد password_hash و جدول users دقیقاً حفظ شود. Migration را فقط روی SQLite خالی آزمایشی اجرا کن؛ دیتابیس واقعی را تغییر نده. تست‌های ساخت مدل، یکتایی قطعه‌ها، مساحت مثبت، محدودیت‌های وضعیت و ارتباط crop_season/plot را اجرا کن.
```

**معیار پایان:** هفت مدل اصلی و Migration قابل‌اجرای آزمایشی بدون تغییر دیتابیس واقعی.

## گام ۳ — کاربران، ورود و خروج

```text
طبق بخش‌های ۲، ۵، ۶.۱ و سناریوهای ۱ و ۲ از بخش ۱۲، endpointهای POST /api/v1/auth/register، POST /login، GET /me و POST /logout را بساز. رمز ۸ تا ۱۲۸ حرف، hash امن Argon2 یا bcrypt؛ شماره موبایل ایران E.164 با تبدیل ارقام فارسی/عربی؛ ایمیل اختیاری و یکتا. access_token باید تصادفی باشد و فقط SHA-256 آن در auth_sessions ذخیره شود؛ TTL پیش‌فرض ۲۴ ساعت و env؛ logout بلافاصله نشست را باطل کند. برای endpointهای محافظت‌شده Bearer اجباری، نبود/خرابی/انقضا 401؛ login ناموفق 401 بدون افشای وجود کاربر؛ ورود را به‌طور ساده rate-limit کن. تست 201/401/409/422 و باطل‌شدن توکن را اجرا کن. هیچ API مزرعه پیاده نکن.
```

**معیار پایان:** ثبت‌نام، ورود، me و logout مطابق قرارداد؛ مالکیت از کاربر احرازشده تعیین می‌شود.

## نکات پرریسک

- **مهاجرت دیتابیس:** Git بکاپ دیتابیس نیست؛ از SQLite واقعی نسخه پشتیبان بگیر و ابتدا روی کپی آزمایش کن.
- **جلسهٔ ورود:** `auth_sessions` توکن تصادفیِ هش‌شده است؛ بدون دلیل آن را JWT یا Session پیش‌فرض Django نکن.
- **قالب خطاها:** 401، 404، 409 و 422 در قرارداد صریح‌اند؛ پیش‌فرض‌های DRF با آن‌ها همیشه یکی نیست.
- **تاریخ‌ها:** تقویم شمسی فقط در فرانت‌اند؛ تاریخ عملیاتی میلادی و منطقه زمانی مزرعه؛ لحظه‌های مطلق UTC با Z.
- **کدپذیری مرحله‌ای:** اگر آزمون گامی شکست خورد، پیش از ورود به مرحله بعد همان را اصلاح کن؛ هر مرحله را با یک کامیت جداگانه نگه دار.
- **پیچیدگی بی‌نیاز:** برای حداکثر ۸ کاربر آزمایشی، همین Django + DRF + SQLite کافی است؛ سرویس صف، Redis و PostgreSQL پیش‌نیاز این نسخه نیستند.
